# Evernote ENEX → Joplin Preparation Tool

A small Python utility that prepares Evernote `.enex` exports for cleaner and safer migration into Joplin.

The script was created while migrating my own Evernote notebooks to a self-hosted Joplin setup. During the migration, I found that importing ENEX files directly into Joplin did not always produce the result I wanted—particularly around image sizing—and some Evernote exports contained malformed XML that caused the entire import to fail.

This tool adds a validation and preprocessing step between Evernote and Joplin.

## Why I Built This

My migration workflow was:

**Evernote → ENEX export → Joplin → self-hosted Joplin Server**

Two issues showed up during testing.

### 1. Large images after import

Importing an ENEX file into Joplin as HTML preserved inline images well, but screenshots and other large images could render much larger than desired.

I wanted imported images to:

- remain inline;
- preserve their aspect ratio;
- fit within the note;
- have a reasonable maximum width; and
- continue working after converting the imported Joplin note from HTML to Markdown.

After testing the migration, the following image styling worked well for my notes:

```css
max-width: 800px;
width: 100%;
height: auto;
```

This script automatically adds that styling to image `<en-media>` elements before the ENEX file is imported into Joplin.

### 2. Invalid XML in Evernote exports

One of my Evernote notebooks repeatedly failed to import into Joplin.

The problem turned out to be malformed XML inside the ENEX generated by Evernote—for example, unescaped text such as:

```xml
<run_id>
```

or:

```text
AR & VR
```

inside XML content.

Instead of attempting potentially destructive automatic repairs, this tool validates the ENEX before modifying it.

If the XML is invalid, the script:

- reports the XML parser error;
- preserves the original ENEX;
- does not modify the note content; and
- stops before image preprocessing.

This makes malformed exports easier to identify and investigate without risking the original Evernote export.

## What the Script Does

Given an Evernote export such as:

```text
My Notebook.enex
```

the script creates:

```text
My Notebook - Ready for Joplin.enex
```

The original export is never intentionally modified.

The processing flow is:

```text
Evernote ENEX
      │
      ▼
Create working copy
      │
      ▼
Validate XML
      │
      ├── FAIL → Stop and report the error
      │
      ▼
     PASS
      │
      ▼
Find image <en-media> elements
      │
      ▼
Apply responsive image sizing
      │
      ▼
Validate XML again
      │
      ├── FAIL → Do not import
      │
      ▼
     PASS
      │
      ▼
Ready for Joplin
```

The second validation is important: it verifies that preprocessing did not leave the ENEX with invalid XML.

---

## Features

- Preserves the original Evernote `.enex` export
- Creates a separate Joplin-ready working copy
- Validates ENEX/XML before making changes
- Detects malformed Evernote exports
- Automatically applies responsive sizing to images
- Validates the resulting ENEX again
- Avoids applying the same image-sizing rule repeatedly
- Uses only the Python standard library
- Does not modify Joplin's database
- Does not require access to your Joplin server

## Requirements

- Python 3
- An Evernote `.enex` export
- Joplin

No third-party Python packages are required.

Check your Python installation with:

```bash
python3 --version
```

## Usage

Clone the repository:

```bash
git clone <YOUR-REPOSITORY-URL>
cd <YOUR-REPOSITORY-NAME>
```

Run the script against an ENEX export:

```bash
python3 prepare_enex.py "/path/to/My Notebook.enex"
```

For example, on macOS:

```bash
python3 prepare_enex.py "$HOME/Downloads/My Notebook.enex"
```

A successful run looks similar to:

The generated file can then be imported into Joplin.

## Recommended Joplin Migration Workflow

The workflow that worked best for my Evernote migration was:

### 1. Export from Evernote

Export the notebook as an `.enex` file.

Keep this original export as your backup.

### 2. Prepare the ENEX

Run:

```bash
python3 prepare_enex.py "/path/to/Notebook.enex"
```

Only continue if you receive:

```text
Final XML validation: PASS

READY FOR JOPLIN
```

### 3. Import into Joplin as HTML

In Joplin:

**File → Import → ENEX – Evernote Export File (as HTML)**

Select:

```text
Notebook - Ready for Joplin.enex
```

I recommend the HTML import path because, in my testing, it preserved inline Evernote images better than importing the ENEX directly as Markdown.

### 4. Inspect the imported notes

Before deleting anything from Evernote, verify:

- note count;
- note content;
- images;
- attachments;
- links;
- formatting; and
- any other important notebook content.

### 5. Convert HTML notes to Markdown

After verifying the imported note, Joplin can convert the HTML note to Markdown.

In my migration, this retained the image presentation while giving me normal Markdown notes.

It also allowed supported YouTube links to render as embedded players in Joplin.

### 6. Sync and verify

Sync Joplin and verify the migrated notes on another device before considering the migration complete.

## Image Processing

The script searches for self-closing Evernote media elements:

```xml
<en-media ... />
```

Only elements whose MIME type begins with:

```text
image/
```

are modified.

The following style is added:

```css
max-width: 800px;
width: 100%;
height: auto;
```

For an image that already contains a `style` attribute, the sizing rules are inserted into that existing attribute.

If no `style` attribute exists, one is created.

### Idempotency

If an image already contains:

```css
max-width: 800px;
```

the script skips it.

This prevents the script from repeatedly inserting its own sizing rule when processing an already-prepared ENEX.

## Handling Invalid ENEX Files

If Evernote generated malformed XML, you may see something such as:

```text
XML validation: FAIL — mismatched tag: line 209581, column 287

The original was preserved.
No image changes were made because the ENEX needs XML repair first.
```

Do **not** import the generated working copy when validation fails.

Use the reported line and column to inspect the original ENEX and determine what Evernote exported incorrectly.

### Why doesn't the script automatically repair malformed XML?

Automatically changing malformed note content can be dangerous.

For example:

```text
Machine Learning, AR & VR
```

may need to be represented in XML as:

```xml
Machine Learning, AR &amp; VR
```

Likewise, text that contains something resembling an XML element may need escaping.

But automatically guessing which text Evernote intended to preserve could modify legitimate note content.

For that reason, the current tool follows a conservative approach:

> Detect the problem, report where it occurred, and leave the original data alone.

---

## Safety

The script deliberately creates a new file rather than modifying the supplied ENEX:

```text
Original:
My Notebook.enex

Generated:
My Notebook - Ready for Joplin.enex
```

Even so, keep your original Evernote exports until you have fully verified your migration.

I also recommend keeping Evernote intact until you have confirmed that all important notes, attachments, images, and metadata have migrated correctly.

---

## What This Tool Does NOT Do

This is a preprocessing utility, not a complete Evernote-to-Joplin migration engine.

It does not:

- connect to Evernote;
- connect to Joplin;
- modify Joplin's database;
- automatically import notes;
- automatically repair malformed XML;
- guarantee preservation of every Evernote-specific feature;
- automatically convert imported HTML notes to Markdown; or
- replace proper backups.

Joplin remains responsible for importing the resulting ENEX file.

## Tested Migration Approach

The tool was developed while moving notebooks from Evernote into a self-hosted Joplin environment.

The tested workflow was:

```text
Evernote
   ↓
ENEX export
   ↓
prepare_enex.py
   ↓
XML validation
   ↓
Image preprocessing
   ↓
XML validation
   ↓
Joplin HTML import
   ↓
HTML → Markdown
   ↓
Joplin sync
```

The initial pilot included notes containing:

- formatted text;
- screenshots and images;
- links;
- YouTube links/embeds; and
- large technical notes.

Because ENEX files and Evernote content can vary considerably, you should still inspect your migrated notes before relying on the result.
